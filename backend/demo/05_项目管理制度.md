# 星辰科技 — 2026 年度项目管理制度

## 第一章 项目管理概述

### 1.1 项目分级

星辰科技所有项目按以下标准分级：

| 级别 | 标准 | 审批人 |
|------|------|--------|
| P0（战略级） | 预算 ≥500 万元，或涉及公司战略方向 | CEO 张明远 |
| P1（重要级） | 预算 100-500 万元，或跨部门协作 | CTO 李博文 / COO 王晓琳 |
| P2（常规级） | 预算 <100 万元，单部门内完成 | 部门总监/经理 |
| P3（维护级） | 日常运维和小修小改 | 组长 |

### 1.2 项目生命周期

```
立项申请 → 评审 → 立项 → 需求分析 → 开发/实施 → 测试 → 上线/交付 → 验收 → 复盘
```

每个阶段需产出对应文档，存放于公司 Confluence 平台。

## 第二章 立项流程

### 2.1 立项申请

项目负责人需提交《立项申请书》，包含：

1. 项目背景和目标
2. 预期收益（收入/效率/客户满意度）
3. 预算估算
4. 人员需求
5. 时间计划
6. 风险评估

### 2.2 评审流程

| 项目级别 | 评审流程 | 评审周期 |
|----------|----------|----------|
| P0 | 立项申请 → 技术评审 → 财务评审 → CEO 审批 | 15 个工作日 |
| P1 | 立项申请 → 技术评审 → CTO/COO 审批 | 10 个工作日 |
| P2 | 立项申请 → 部门经理审批 | 5 个工作日 |
| P3 | 组长审批即可 | 2 个工作日 |

**技术评审负责人**：周建华（后端组组长）、黄伟（算法组组长）
**财务评审负责人**：赵国强（CFO）

## 第三章 开发流程

### 3.1 敏捷开发规范

技术部和研发中心统一采用敏捷开发模式：

- **迭代周期**：2 周为一个 Sprint
- **站会**：每天 9:30，15 分钟以内
- **Sprint 计划会**：每个 Sprint 第一天，2 小时以内
- **Sprint 回顾会**：每个 Sprint 最后一天，1 小时
- **Scrum Master**：由各组组长轮流担任

### 3.2 代码管理

| 分支类型 | 命名规范 | 说明 |
|----------|----------|------|
| main | main | 生产环境代码，仅接受合并请求 |
| develop | develop | 开发主干分支 |
| feature | feature/JIRA-编号-简短描述 | 功能开发分支 |
| bugfix | bugfix/JIRA-编号-简短描述 | Bug 修复分支 |
| release | release/v版本号 | 发布分支 |
| hotfix | hotfix/JIRA-编号-简短描述 | 紧急修复分支 |

**代码规范**：
- Python：ruff 格式化 + type hints
- 前端：ESLint + Prettier
- 所有代码合并前必须通过 CI（单元测试 + 集成测试）

**代码仓库管理员**：吴晓峰（运维组组长）

### 3.3 测试要求

| 测试类型 | 负责方 | 完成标准 |
|----------|--------|----------|
| 单元测试 | 开发人员 | 覆盖率 ≥80% |
| 集成测试 | 开发人员 | 关键接口 100% 通过 |
| 系统测试 | 测试组（归属运维组） | 无 P0/P1 级别 Bug |
| 用户验收测试 | 产品组 + 客户 | 客户签字确认 |

### 4.2 项目汇报机制

- **周报**：每周五提交，项目负责人撰写，发送至 CTO 李博文
- **月报**：每月最后一天，CTO 汇总所有项目状态，发送给 CEO 张明远和 COO 王晓琳
- **季度评审**：每季度末，CEO 张明远主持项目评审会

## 第五章 风险管理

### 5.1 风险等级

| 等级 | 影响范围 | 响应时间 |
|------|----------|----------|
| 高 | 影响生产环境或客户交付 | 2 小时内响应 |
| 中 | 影响开发效率或测试环境 | 8 小时内响应 |
| 低 | 不影响正常交付 | 24 小时内响应 |

### 5.2 风险预案

每个 P0/P1 项目必须制定风险预案，包括：

1. 关键技术风险的替代方案
2. 核心人员离职的应对措施
3. 预算超支的应急计划
4. 需求变更的处理流程

**风险管理协调人**：赵国强（CFO）
