## 第二章 架构设计原则

### 2.1 分层架构

后端统一采用四层架构：

```
路由层（routers/）    → 请求解析、认证、响应装配
    ↓
服务层（services/）    → 业务逻辑编排
    ↓
仓储层（repositories/）→ 数据访问
    ↓
模型层（models/）      → 数据结构定义
```

**关键约束**：
- 路由层保持薄，不超过 50 行/文件
- 服务层是业务逻辑的唯一归属
- 仓储层封装所有数据库查询，路由不得绕过仓储直接操作模型

### 2.2 智能体架构

基于 LangGraph v1 的多智能体架构：

```
用户请求 → AgentView → API → Chat Service
                              ↓
                    LangGraph State Machine
                    ├── BaseAgent（主智能体）
                    │   ├── KnowledgeBaseMiddleware（知识库）
                    │   ├── SkillsMiddleware（技能）
                    │   ├── MCPs（外部工具调用）
                    │   └── Toolkits（内置工具集）
                    └── Worker（ARQ 异步执行）
```

### 2.3 微服务演进

智能客服平台 v5.0（项目 B）将采用微服务架构：

| 服务 | 职责 | 部署方式 |
|------|------|----------|
| API Gateway | 路由分发、认证、限流 | 独立容器 |
| Dialog Service | 对话管理、状态维护 | 2 实例 |
| LLM Proxy | 大模型调用、缓存、负载均衡 | 3 实例 |
| Knowledge Service | 知识库检索 | 2 实例 |
| Ticket Service | 工单处理 | 1 实例 |
| Analytics Service | 数据统计、看板 | 1 实例 |

## 第三章 API 设计规范

### 3.1 路径规范

- 统一前缀：`/api/v1/`
- 资源用复数名词：`/api/v1/users`、`/api/v1/knowledge-bases`
- 嵌套资源：`/api/v1/users/{id}/knowledge-bases`
- 操作用 POST + 动词后缀：`/api/v1/knowledge-bases/{id}/query`

### 3.2 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

错误码规范：
- 0：成功
- 400xx：客户端错误
- 500xx：服务端错误

### 3.3 认证机制

- 内部 API：JWT Token
- 外部 API Key：Bearer Token
- 管理员接口：需要 SuperAdmin 角色

## 第四章 数据安全

### 4.1 数据分类

| 等级 | 数据类型 | 存储要求 |
|------|----------|----------|
| 绝密 | 客户合同、财务数据、源代码 | 加密存储，仅内网访问 |
| 机密 | 客户信息、员工信息 | 加密存储，权限控制 |
| 内部 | 项目文档、会议记录 | 内网访问 |
| 公开 | 产品白皮书、官网内容 | 可外网访问 |

### 4.2 备份策略

| 数据类型 | 备份频率 | 保留时间 | 备份方式 |
|----------|----------|----------|----------|
| PostgreSQL | 每日全量 + 每小时增量 | 30 天 | 异地备份 |
| MinIO 对象存储 | 每日增量 | 7 天 | 同城备份 |
| Neo4j 图谱 | 每周全量 | 4 周 | 本地备份 |
| Milvus 向量数据 | 每日全量 | 14 天 | 异地备份 |
